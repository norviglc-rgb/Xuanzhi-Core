# N8N_INTEGRATION.md

## 1. 文档目的
定义 n8n 在 Xuanzhi-Core 系统中的角色、边界、接入方式与当前状态。

---

## 2. 组件定位
n8n 是当前系统中的**定时任务、自动化、编排系统**。

它负责：
- 定时触发
- 自动化任务链路
- 跨系统流程编排
- 事件驱动式衔接

---

## 3. 与 Xuanzhi-Core 的关系
Xuanzhi-Core 负责治理与收敛；
n8n 负责自动化执行和编排。

两者关系是：
- Xuanzhi-Core 决定规则与边界
- n8n 执行可自动化的流程链路
- 需要进入治理、审核、记录的节点应回传到 Xuanzhi-Core

---

## 4. 边界
n8n 不负责：
- 项目治理总则定义
- 宪章与边界定义
- 风险模型源头
- 审批规则源头

---

## 5. 输入输出关系

### 5.1 输入来源
- 定时任务触发（Cron 表达式）
- 外部事件（Webhook）
- 来自治理层的自动化触发指令
- 来自 NocoBase 的审批结果通知

### 5.2 输出内容
- 自动化执行结果
- 状态通知
- 审批前置或后置结果
- 可写入记忆或审计的记录

---

## 6. 触发器列表

### 6.1 定时触发器
| 触发器名称 | 触发周期 | 用途 |
|-----------|---------|------|
| daily_brief_trigger | 每日 09:00 | 触发日报生成流程 |
| weekly_review_trigger | 每周一 10:00 | 触发周报生成流程 |
| memory_cleanup_trigger | 每周日 02:00 | 清理过期记忆 |
| health_check_trigger | 每 5 分钟 | 系统健康检查 |

### 6.2 事件触发器
| 触发器名称 | 触发条件 | 用途 |
|-----------|---------|------|
| approval_completed | NocoBase 审批完成 | 继续后续流程 |
| mr_merged | GitLab MR 合并 | 触发部署流程 |
| task_failed | 任务执行失败 | 触发告警通知 |

## 7. 与其他组件的协作方式

### 7.1 与 NocoBase 的审批协作
```
n8n 流程执行
  -> 遇到需要审批的节点
    -> 调用 NocoBase API 创建审批单
      -> 暂停流程等待
        -> NocoBase 审批完成回调
          -> n8n 继续执行
```

### 7.2 与 Coze Studio 的协作
```
n8n 触发事件
  -> 调用 Coze Studio 应用 API
    -> 应用通过 Higress 访问模型
      -> 结果返回 n8n
        -> 后续处理或记录
```

### 7.3 与 Higress/QMD 的协作
```
n8n 流程需要模型能力
  -> 通过 Higress 调用模型
    -> 需要检索时调用 QMD
      -> 结果汇总处理
        -> 回传 Xuanzhi-Core 记录
```

## 8. 失败重试和异常回收策略

### 8.1 重试策略
- 默认重试次数：3 次
- 重试间隔：指数退避（1s, 2s, 4s）
- 最大重试间隔：60 秒

### 8.2 异常处理
- 重试耗尽后：记录失败日志，通知治理层
- 关键流程失败：触发告警，等待人工介入
- 非关键流程失败：记录后跳过，不影响主流程

### 8.3 错误通知
- 通过 Webhook 通知 Xuanzhi-Core
- 高优先级错误同时通知人工
