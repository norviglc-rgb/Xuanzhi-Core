# HIGRESS_INTEGRATION.md

## 1. 文档目的
定义 Higress 在 Xuanzhi-Core 系统中的角色、边界、接入方式与当前状态。

---

## 2. 组件定位
Higress 是当前系统中的**模型入口网关 / 路由层**。

它负责：
- 统一模型访问入口
- 模型路由与代理
- 鉴权、网关策略、流量治理
- 为 AI 执行层提供统一模型接入面

---

## 3. 与 Xuanzhi-Core 的关系
Xuanzhi-Core 负责治理与路由决策；
Higress 负责模型访问入口与流量控制。

两者关系是：
- Xuanzhi-Core 决定"是否需要模型能力、由哪类路径触发"
- Higress 负责"模型入口如何被统一访问和治理"

---

## 4. 边界
Higress 不负责：
- 项目目标定义
- 风险规则定义
- 审批策略定义
- 工作流治理定义

这些仍属于 Xuanzhi-Core 的治理层。

---

## 5. 输入输出关系

### 5.1 输入来源
- 来自 Coze Studio 的模型请求
- 来自 Claude Code 相关链路的模型调用
- 来自自动化流程（n8n）的模型能力请求
- 来自 FastGPT 的模型调用

### 5.2 输出内容
- 统一模型调用结果
- 路由 / 网关层返回信息
- 可供治理层记录的调用结果或状态

---

## 6. 接入协议

### 6.1 API 格式
Higress 提供与 OpenAI 兼容的 API 接口：
- `/v1/chat/completions` - 对话补全
- `/v1/embeddings` - 向量嵌入
- `/v1/models` - 模型列表

### 6.2 鉴权模式
- API Key 鉴权（Header: `Authorization: Bearer <key>`）
- 支持多租户隔离
- 密钥轮换策略由 NocoBase 后台管理

### 6.3 路由策略
- 按模型名称路由到不同后端
- 支持负载均衡和故障转移
- 支持请求超时和重试配置

---

## 7. 日志与审计

### 7.1 日志落点
- 请求日志：记录调用时间、来源、模型、token 消耗
- 错误日志：记录失败原因、重试次数
- 审计日志：记录敏感操作和异常调用

### 7.2 与 Trace 系统集成
- 生成 `trace_id` 关联完整调用链
- 支持与 TRACE_SPEC.md 定义的追踪规范对接

---

## 8. 与其他组件的调用样例

### 8.1 Coze Studio -> Higress
```
Coze Studio 应用
  -> Higress API Gateway
    -> 路由到指定模型
      -> 返回结果
        -> 记录到 Xuanzhi-Core
```

### 8.2 Claude Code -> Higress
```
Claude Code 执行
  -> 需要模型能力时
    -> 通过 Higress 调用
      -> 结果返回执行器
        -> 最终汇报给 Xuanzhi-Core
```
